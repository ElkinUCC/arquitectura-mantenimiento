# E03 - Diagrama C4 Context

**Solicitud empresarial:**

Representar quién utiliza el sistema de mantenimiento y cómo interactúa con él para registrar y consultar órdenes.

**Versión/fecha/entorno:**

- Versión: completar.
- Fecha: completar.
- Entorno: diagrams.net y documentación del proyecto.
- Responsable: estudiante.

**Archivos y componentes observados:**

- `frontend/index.html`.
- `backend/app/ordenes/controladores.py`.
- Requisitos RF-01 y RF-02.
- Diagrama `expediente/diagramas/contexto.drawio`.

**Acciones reproducidas, paso a paso:**

1. Identificar los actores del caso empresarial.
2. Crear una caja denominada Sistema de gestión de mantenimiento.
3. Ubicar fuera de la caja al operador de operaciones y al coordinador de equipos.
4. Dibujar las relaciones de consulta y registro.
5. Exportar el diagrama a PDF.

**Resultado observado (captura, prueba, log):**

Pendiente de adjuntar el diagrama creado y exportado. El resultado esperado es una vista del sistema completo y sus actores externos.

**Interpretación arquitectónica:**

C4 Context presenta el límite del producto y las relaciones con su entorno. No debe incluir tablas, clases ni módulos internos.

**Clasificación: OBSERVADO / CÓDIGO / DOCUMENTADO / SUPUESTO / PROPUESTO**

DOCUMENTADO cuando el diagrama esté elaborado. CÓDIGO para las relaciones contrastadas con funciones verificadas.

**Riesgo, alternativa y pendiente:**

No se deben representar integraciones externas ni permisos de usuario sin evidencia. Está pendiente verificar que cada relación corresponda al alcance real.

**Criterio de aceptación comprobado:**

Pendiente. El diagrama debe mostrar el sistema, los actores y las relaciones etiquetadas, con una frontera coherente.
