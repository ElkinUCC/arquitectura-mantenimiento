# E05 - Propuesta arquitectónica inicial

**Solicitud empresarial:**

Mantener las funciones de registro y consulta de órdenes y estudiar una arquitectura que permita evolucionar el sistema sin complejidad innecesaria.

**Versión/fecha/entorno:**

- Versión: completar.
- Fecha: completar.
- Entorno: revisión del código y de las evidencias E01–E04.
- Responsable: estudiante.

**Archivos y componentes observados:**

- Controladores, servicios, repositorios y modelos de órdenes.
- Frontend web.
- Diagramas C4 Context y Container.
- Evidencias E01–E04.

**Acciones reproducidas, paso a paso:**

1. Revisar los requisitos identificados.
2. Contrastar los requisitos con el código y los diagramas.
3. Describir la arquitectura actual.
4. Comparar el monolito modular con una organización de código concentrado.
5. Documentar beneficios, riesgos y datos pendientes.

**Resultado observado (captura, prueba, log):**

Pendiente de completar con las referencias verificadas de E01–E04. La propuesta debe quedar documentada en este archivo.

**Interpretación arquitectónica:**

El monolito modular separa el manejo HTTP, las reglas de negocio y la persistencia sin requerir múltiples servicios desplegados independientemente.

**Clasificación: OBSERVADO / CÓDIGO / DOCUMENTADO / SUPUESTO / PROPUESTO**

PROPUESTO para la recomendación arquitectónica y CÓDIGO para la descripción de la estructura existente.

**Riesgo, alternativa y pendiente:**

La separación por módulos requiere controlar las dependencias. Faltan datos de uso, seguridad, operación y crecimiento para determinar si se necesita una arquitectura diferente.

**Criterio de aceptación comprobado:**

Pendiente. Deben existir al menos dos alternativas comparadas y una trazabilidad entre necesidad, evidencia, opción, beneficio y limitación.
