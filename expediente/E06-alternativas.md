# E06 - Comparación de SOA, microservicios y eventos

**Solicitud empresarial:**

Evaluar si la evolución de la gestión de órdenes justifica mantener la arquitectura actual o adoptar una arquitectura distribuida.

**Versión/fecha/entorno:**

- Versión: completar.
- Fecha: completar.
- Entorno: análisis documental y revisión del código.
- Responsable: estudiante.

**Archivos y componentes observados:**

- Módulo de órdenes del backend.
- Evidencia E05.
- Diagramas C4.
- Requisitos empresariales disponibles.

**Acciones reproducidas, paso a paso:**

1. Identificar necesidades que puedan exigir despliegues independientes.
2. Comparar monolito modular, SOA, microservicios y arquitectura orientada a eventos.
3. Evaluar autonomía, integración, coordinación, gestión de fallos y costos.
4. Relacionar cada alternativa con las necesidades confirmadas.
5. Documentar la decisión provisional.

**Resultado observado (captura, prueba, log):**

Pendiente de registrar la matriz comparativa final. La conclusión debe sustentarse en los requisitos y restricciones disponibles.

**Interpretación arquitectónica:**

El monolito modular es una alternativa razonable para el caso de referencia. No existe evidencia aportada que obligue a distribuir la aplicación en varios servicios.

**Clasificación: OBSERVADO / CÓDIGO / DOCUMENTADO / SUPUESTO / PROPUESTO**

DOCUMENTADO para la comparación y PROPUESTO para la decisión provisional.

**Riesgo, alternativa y pendiente:**

SOA, microservicios y eventos pueden introducir costos de integración, monitoreo, coordinación y consistencia. La decisión debe revisarse si aparecen necesidades comprobadas de autonomía o integración.

**Criterio de aceptación comprobado:**

Pendiente. La matriz debe presentar las cuatro alternativas, sus beneficios y costos, y una recomendación vinculada con necesidades verificables.
